# Engineering notes

This document keeps the implementation decisions, discarded rendering paths and measured device results behind the current firmware. It is a development record, not a guarantee that every observation reproduces on every unit.

## 产品闭环

用户通过触摸、滑动、实体按键或语义命令触发表情；设备用动画和短震动立即回应。`idle`、`listening`、`thinking` 可持续停留，其余短暂反应结束后回到触发前的持续状态。

## 当前表情

| 表情 | 视觉行为 | 默认触发 |
| --- | --- | --- |
| `idle` | 呼吸、眨眼、微扫视和多个观察方向 | 启动默认状态 |
| `listening` | 轻微侧头、两眼交替聚焦，保持注意 | 语音/外部状态 |
| `thinking` | 视线偏移、双眼不对称、慢速思考节奏 | 语音/外部状态 |
| `happy` | 预备压缩、舒展成笑眼、轻微回弹 | 单击 |
| `excited` | 快速压缩、放大弹起、笑眼落定 | 浏览/外部命令 |
| `curious` | 一侧睁大并歪头观察 | 浏览/外部命令 |
| `confused` | 双眼大小和倾角交替、最后皱眉 | 横向滑动反应/外部命令 |
| `angry` | 双眼内倾收紧、眉毛下压、快速颤动 | 长按 |
| `surprised` | 先眯起再迅速张圆、轻微回弹 | 双击或向上滑动 |
| `sad` | 眉线内侧抬起、眼皮下垂、低头停留 | 低电量、联网失败/外部命令 |
| `sleepy` | 眼皮下垂、眼睛缓慢闭合并下沉 | 低电量/夜间状态 |
11 种表情不再暴露为用户可前后翻动的目录，而由触摸方向、动作、电量、充电、联网和外部语义事件选择。普通界面长按 A 打开眼睛菜单，短按 A/B 均不切换表情；同时长按 A+B 约一秒仍进入或退出硬件诊断模式。

## 连续触摸与动作交互

- 手指按住屏幕时，眼睛先看向当前触点，虚拟头部用较慢的弹簧跟随；拖动过程中每帧更新，不需要等到手指离开后才反馈；
- 手指松开后，眼睛和头部以不同速度回到设备当前倾斜方向，不再整体硬切回中心；
- 横向手势移动约 `12 px` 后锁定方向，整张脸随拖动距离移动并轻微歪头；超过约 `52 px` 时根据方向触发一次好奇或困惑反应，不浏览表情目录；
- 每次手势最多提交一次情境反应；未达到触发距离时，脸部在松手后弹回，避免轻微移动误触；
- 纵向滑动同样在达到约 `52 px` 时立即响应：向上触发惊讶反应，向下打开沉浸式电量查看；
- 没有触摸时，IMU 的横纵倾斜会让眼睛持续跟随，头部用较慢弹簧随后转向；保持倾斜时视线不会立即回中，触摸优先级高于倾斜；
- IMU 原始 X/Y 按照官方 StopWatch 示例交换为屏幕横纵坐标；快速移动只映射为短暂惯性反馈，不切换当前表情；
- 单击、双击、长按和横向/向上滑动仍映射为短暂情境反应；向下滑动查看电量，A/B 不再直接选择表情。

触摸跟随、回弹和倾斜只作为位置偏移叠加到当前表情，不会重置关键帧时间轴或替换表情。因此用户可以在任意表情播放期间继续触摸眼睛，而表情仍会正常完成并返回当前基础状态。

### 2.5D 头眼模型

在不绘制角色身体、继续使用纯黑背景的前提下，渲染器把两只眼睛视为贴在一个不可见的球形头部上。头部横转时双眼间距会压缩，靠近转向侧的眼睛略大、另一侧略小；俯仰会改变眼睛高度，歪头会让双眼围绕面部中心旋转并改变各自角度。

待机不再依靠固定正弦曲线持续左右摆动，而是在五个观察方向之间长时间停留并平滑转向，同时叠加短促微扫视。自然眨眼总时长从约 `196 ms` 放缓到 `280 ms`，随机间隔调整为 `3.4 - 6.2 s`。

所有产品表情帧必须使用纯黑背景，只允许白色或浅灰色的眼睛和表情线条；不绘制彩色角色身体、彩色腮红、彩色标签或操作提示。硬件诊断模式不受这条产品视觉规则约束。

## 语音接入边界

动画层只接收语义表情事件。当前串口命令用于模拟未来语音识别结果，因此接入麦克风和离线命令词时，不需要修改表情渲染和过渡逻辑。

语音阶段开始前先完成：

1. StopWatch 麦克风采集和采样率实机验证；
2. 音频电源域、内存占用和持续监听功耗测量；
3. Arduino/PlatformIO 与 ESP-SR 的集成路径验证；
4. 推按说话或唤醒词方案选择。

## 第一轮真机验收

- 启动后能看到 `idle`，持续运行时无明显闪屏或重启；
- 单击、双击和长按不会互相误判；
- 四个滑动方向在圆屏中心和主要可触区域都能稳定识别；
- A 能打开并操作眼睛菜单，B 能返回且不会切换表情，A+B 长按能可靠进入及退出诊断；
- 表情过渡和自动返回完整，震动不会卡住动画；
- 诊断模式能继续显示触摸坐标和 IMU 数据；
- 串口 12 条英文命令都能触发对应表情。

这些项目必须烧录真实 StopWatch 后逐项确认；`pio run` 成功不能代替验收。

## V2 第一阶段基准

- 产品画面继续严格使用纯黑背景和白色/浅灰眼睛，不增加嘴、文字或彩色元素；
- 表情几何改用 `1000 x 1000` 归一化设计坐标，再按实际屏幕短边缩放；
- `idle` 两眼视觉组合宽度约占 466 圆屏直径的 60%，作为后续表情的尺寸基准；
- 渲染目标先设为约 60 fps，每 5 秒通过串口输出实际 fps、平均/最大渲染耗时及帧间隔；
- 是否采用全屏刷新、局部刷新或降低目标帧率，必须根据真机数据决定；
- 在这张基准脸经过真机视觉确认前，不批量制作 V2 表情库。

### 2026-08-21 真机性能记录

V2 大眼基准固件已成功编译并烧录至连接的 ESP32-S3R8。保持整张
`466 x 466`、16 位 PSRAM 画布并调用 `pushSprite(0, 0)` 时，连续四个约
5 秒采样窗口得到：

- 实际帧率：`11.9 - 12.4 fps`；
- 平均单帧渲染及传输耗时：约 `75.7 ms`；
- 最大单帧渲染及传输耗时：约 `77.2 ms`；
- 最大帧间隔：约 `84.0 ms`。

这证明当前全屏传输路径无法达到 45/60 fps。进入动画系统重构前，应先
验证只刷新眼睛活动区域的局部画布，并重新测量帧率和触摸主循环延迟。
以上数据证明固件已运行并输出性能日志；眼睛尺寸、位置和动画观感仍需
观察设备屏幕后进行视觉验收。

### 局部刷新与连续模型复测

将整屏画布替换为双眼动态脏矩形，并让常规圆角眼使用显示驱动原生填充
后，`idle` 连续窗口稳定在 `55.5 - 55.8 fps`，平均渲染约 `6.0 ms`。

随后移除动画中途硬切的 `EyeStyle`，改为左右眼独立的宽度、高度、位置、
圆角、上下眼皮和眉线参数；六种表情分别使用 1 至 3 个可中断关键帧，支持
`smooth`、`snappy` 和 `spring` 三种缓动。串口连续轮测六种状态时：

- 五秒窗口帧率约 `53.1 - 54.5 fps`；
- 窗口平均渲染耗时约 `2.8 - 8.7 ms`；
- 观察到的最大渲染耗时约 `12.7 ms`；
- 触发表情、震动和串口日志同时发生时，最大帧间隔约 `48.8 ms`。

代码已通过 `pio run` 并成功烧录。以上证明性能和设备端事件链路；具体
动作节奏、眉线造型和情绪辨识度仍需人工观察屏幕后验收。

### 60 fps 帧调度与动作曲线复测

将毫秒级轮询改为 `16667 us` 固定帧调度，并把主循环协作延时从 `5 ms`
缩短为 `1 ms` 后，`idle` 连续窗口稳定在 `60.0 fps`，平均帧间隔为
`16.67 ms`。同时延长过短的关键帧、使用五次平滑曲线处理常规过渡，并
为眨眼及表情附加运动增加独立的进入/退出渐变。

为避免触发震动时阻塞动画，运行期 PWM 更新改为单次两字节寄存器写入；
串口依次触发六种表情时：

- 五秒窗口帧率约 `60.0 - 60.4 fps`；
- 窗口平均渲染耗时约 `3.2 - 8.1 ms`；
- 观察到的最大渲染耗时约 `12.7 ms`；
- 表情与震动触发期间最大帧间隔约 `18.2 ms`。

代码已再次通过 `pio run` 并烧录至连接设备。串口确认六种表情命令均被
接受；动作观感和震动体感仍需观察设备进行人工验收。

### 动画引擎 2.0：数据驱动播放目录

六种动画现在通过同一个配置目录声明关键帧、默认播放方式、眨眼策略和
持续运动参数。时间轴支持 `once`、`loop`、`pingpong` 三种播放方式；
每个动画可以分别启用或关闭眨眼，并配置首次眨眼、随机间隔和闭眼/睁眼
时长。待机生命运动与当前情绪运动通过通用振荡器采样和渐变混合，不再在
渲染函数中为每种表情维护独立条件分支。

简单表情命令仍保持原来的播放并自动回到待机；调试串口新增
`once|loop|pingpong <expression>` 语法，用于验证播放模式。新动画可以
复用同一套时间轴和运动组件，不需要修改屏幕绘制路径。

该版本已通过 `pio run` 并成功烧录至连接的 StopWatch。串口依次确认六种
普通表情命令，以及 `loop happy`、`pingpong thinking`、`once surprised`
播放命令均被接受。轮测期间：

- 五秒窗口帧率约 `60.0 - 60.2 fps`；
- 平均帧间隔约 `16.6 - 16.67 ms`；
- 观察到的最大帧间隔约 `18.0 ms`；
- 观察到的最大渲染耗时约 `12.82 ms`。

以上证明新目录、播放命令和设备渲染链路持续运行；具体循环方向、独立
眨眼节奏和动画观感仍需观察屏幕进行人工验收。

### 连续触摸与 IMU 交互复测

新增一层独立于表情时间轴的视线弹簧：触摸坐标映射到归一化设计空间，
按住时使用较高刚度跟手，松开后使用较低刚度回弹；未触摸时由经过低通
滤波和启动校准的 IMU 倾斜量提供目标位置。快速晃动使用三轴相邻采样的
加速度突变量生成短暂惯性，不会替换当前表情。

该版本已通过 `pio run` 并烧录至连接的 StopWatch。烧录后连续五个稳定
采样窗口均为 `60.0 fps`，平均帧间隔 `16.67 ms`，稳定窗口最大帧间隔约
`17.9 ms`，平均渲染耗时约 `5.9 - 6.0 ms`。这证明触摸/IMU 采样和弹簧
计算没有降低持续帧率；触摸方向、回弹手感、倾斜方向和摇晃阈值仍需在
设备上实际操作后完成人工验收。

### 2.5D 头眼模型真机复测

第一版旋转眼睛最初使用抗锯齿宽线，在转向阶段平均渲染耗时约 `37 ms`，
实际帧率降至约 `24 fps`，因此未作为可交付实现保留。随后改为两个实心
圆端帽加两个三角形组成旋转胶囊，只使用显示驱动的快速填充路径。

优化版已通过 `pio run` 并烧录至连接的 StopWatch。稳定窗口帧率为
`60.0 - 60.2 fps`，平均渲染耗时约 `5.8 - 6.9 ms`，观察到的最大稳定
帧间隔约 `19.6 ms`。补测 `ANGRY` 与 `SLEEPY` 时平均渲染耗时最高约
`9.4 ms`、最大约 `12.83 ms`，帧率仍为约 `60 fps`。设备日志同时记录到触摸触发 `HAPPY`、`SURPRISED`。
以上证明 2.5D 投影、旋转胶囊绘制和输入链路
可以在目标帧率下共同运行；头部方向、转向幅度、边缘质量和角色观感仍需
目视真机完成验收。

用户确认第一版 2.5D 方向正确，但认为移动幅度偏小。随后将待机最大横转
从约 `19°` 提高到 `27°`，触摸最大横转从约 `25°` 提高到 `32°`，并同步
增强俯仰、歪头、眼间距压缩和近大远小差异。增强版再次编译、烧录并经过
完整待机方向循环，稳定窗口保持 `60.0 fps`，平均渲染约 `6.5 - 7.3 ms`，
观察到的最大稳定帧间隔约 `18.6 ms`；最终幅度仍以目视真机确认。

### 表情库 V3：11 种表情与基础状态

目录新增 `listening`、`thinking`、`excited`、`curious`、`confused`、`sad`
六种表情；移除一个特殊反应后当前总数为 11 种。所有动画继续复用程序化关键帧、连续插值、
眨眼策略、生命运动和 2.5D 头眼投影，没有增加图片序列帧或彩色背景。

状态机现在区分两类表情：`idle`、`listening`、`thinking` 是持续基础状态；
其余八种是短暂反应。短暂反应完成后返回当前基础状态，而不是固定返回
`idle`。用户交互只触发与动作相符的短暂反应，不修改持续基础状态，也不提供目录游标。

2026-08-22 已通过 `pio run` 并烧录至连接的 StopWatch。串口轮测确认表情
普通表情命令均被接受，且两条代表性返回链符合预期：
`LISTENING → HAPPY → LISTENING`、`THINKING → CONFUSED → THINKING`。
快速连续触发新增表情时，采样窗口约 `60.0 - 60.3 fps`，平均渲染约
`5.95 - 7.50 ms`，观察到的最大帧间隔约 `18.63 ms`。这些结果证明代码、
烧录、时间轴和状态返回链路可运行；六种新增表情的辨识度、动作幅度以及
按键/滑动连续浏览手感仍需目视并操作真机确认。

### 连续跟手滑动

旧版只在触摸库报告 `flick_end` 或 `drag_end` 后切换表情，因此必须等待
手指离开屏幕；拖动期间只有视线跟随，表情时间轴也要在松手后才启动。
新版把触摸移动阈值从 `28 px` 降为 `10 px`，在 `12 px` 时锁定方向，
并将拖动距离逐帧映射为整脸位移、歪头、轻微压缩和相邻表情预演。

横向或纵向位移达到 `52 px` 时会立即且只提交一次切换；位移不足则弹回。
滑动提交使用 `160 ms` 的首段快速衔接，后续仍按各表情自己的关键帧节奏
播放。首次真机反馈发现，提交切换后代码停止更新本次触点，导致新表情在
手指仍按住时脱离。修正版保持同一触点持续有效直到松手，并将横向位移比例
从 `0.72` 提高到 `0.96`、最大位移从 `82 px` 提高到 `130 px`。

修正版已通过 `pio run` 并烧录至连接设备。烧录后待机采样持续为
`60.0 fps`，平均渲染约 `6.5 - 7.3 ms`，观察到的最大帧间隔约
`18.57 ms`。这些数据证明新增插值和回弹没有降低待机性能；真实手指下的
方向锁、切换距离、回弹力度和主观跟手感仍需人工操作确认。

### 眼睛边缘灰阶羽化

眼睛原先直接使用整数像素的圆角矩形、圆形和三角形填充，旋转胶囊和斜
眼皮尤其容易在纯黑与纯白之间形成明显台阶。第一轮尝试直接使用 M5GFX
平滑圆角和透明混合：待机渲染升至约 `13.2 - 13.6 ms`；持续播放
`ANGRY` 时降到约 `54.0 - 55.8 fps`，因此未保留。

最终方案不读取屏幕像素、不做透明混合，而是在白色主体外快速绘制约
`1 px` 的单档灰色覆盖边。普通眼睛使用扩大一像素的灰色圆角底层，旋转
胶囊使用扩大半径的灰色三角形和圆端帽，斜眼皮在黑白交界处补一条灰线。
这不能等同于高倍超采样，但能降低黑白高反差造成的锯齿感，同时保留快速
硬件填充路径。

2026-08-24 该版本已通过 `pio run` 并烧录到连接的 StopWatch。真机串口
复测结果：

- `IDLE` 稳定 `60.0 fps`，平均渲染约 `7.9 - 8.6 ms`；
- `LISTENING` 稳定 `60.0 fps`，平均渲染约 `7.3 ms`；
- 持续 `ANGRY` 稳定约 `60.0 fps`，平均渲染约 `11.6 - 12.3 ms`；
- 持续 `SAD` 稳定 `60.0 fps`，平均渲染约 `9.5 - 11.2 ms`；
- 触摸触发 `HAPPY` 与 IMU 惯性反馈的窗口仍约 `60.1 fps`。

以上证明灰阶羽化、动画和输入链路可以共同维持目标帧率；灰边亮度是否
足够自然以及锯齿改善程度，仍以目视真机为最终验收。

后续真机观察到移动眼睛的一像素中灰轮廓会在 AMOLED 上出现 RGB 子像素
分离，视觉上像彩色拖尾，因此移动轮廓改回纯白，并把脏矩形保护边距从
`4 px` 扩为 `7 px`。文字最初使用四次灰色偏移加一次黑色主体来模拟柔边；
局域网消息真机测试发现消息出现时单帧峰值达到 `44.26 ms`，因此改为每只眼
每帧只栅格化一次字形，优先保证表情运动连贯。消息启动路径也不再额外请求
全屏清黑；亮屏时复用既有双眼脏矩形，只有从 AMOLED 息屏状态唤醒时才保留
必要的全屏重绘。消息退出并恢复基础表情时同样沿用脏矩形，不再人为制造
一次整屏传输。

2026-08-27 真机目视反馈指出，愤怒表情的斜眼皮内侧出现一条多余白线。第一轮
排查发现黑色三角形裁切上眼皮后，渲染器又沿裁切边界补画了白色直线；该直线与
独立眉线叠加后形成双线，因此先移除了眼内的白色边界线。眉线同时从抗锯齿宽线
改为两个实心三角形加圆端帽组成的快速胶囊。优化前持续 `ANGRY` 约为 `35.8 fps`，
平均渲染约 `24.0 ms`；优化后持续 `ANGRY` 稳定为 `59.7 fps`，平均渲染约
`12.9–13.1 ms`，最大 `15.05 ms`，TE 同步 `100%`，帧超时为 `0`。

第二轮目视反馈确认右眼附近仍有一条多余线。代码复查后，愤怒表情中剩余的独立
线条只有眉线；三帧左右眼仍分别保留 `0.72`、`1.0` 和 `0.85` 的眉线透明度。
本轮将六处透明度全部归零，保留左右相反倾角的黑色上眼皮裁切来表达愤怒，避免
右眼再出现游离线段。最终造型仍需在真实 StopWatch 屏幕上目视确认。

第三轮目视反馈表明右眼线段依然存在。再次复查完整绘制顺序后确认，愤怒眼虽然已
没有眉线和显式边界线，但仍先绘制向外扩一像素的白色圆角眼，再用左右相反的黑色
三角形裁切斜眼皮；反向裁切可能在右眼外轮廓留下独立白色栅格边。为彻底排除这一
类叠加残留，愤怒的三帧改为直接绘制左右内倾的窄胶囊眼，不再设置上眼皮、斜眼皮、
下眼皮或眉线。胶囊内部仍由同色实心几何拼合，因此不存在独立表情线或黑色裁切边。
新造型与右眼残线是否彻底消失仍需用户观察真实 AMOLED 后确认。

用户确认无裁切的内倾胶囊眼已经消除多余线段，并希望恢复眉毛。后续版本保留这套
胶囊眼，不恢复任何眼皮裁切；只在眼睛上方加入左右对称、向内下压的独立眉毛。
旋转快速路径不再以“没有眉毛”为前提，因此胶囊眼的内倾角度与眉毛可以同时存在。
三帧眉毛透明度依次为 `0.62 / 0.82 / 0.72`，眉线本身仍沿用实心三角形与圆端帽
组成的快速胶囊，不使用抗锯齿宽线。

眼睛菜单原先默认以 `curious` 的多关键帧 `pingpong` 播放，因此左右眼宽高会交替
变化，左眼呈现持续放大缩小。菜单默认眼型改为单关键帧 `idle`，保留自然眨眼、
轻微整体呼吸、触摸与 IMU 跟随，不再循环改变单只眼睛尺寸。网络连接、连接中和
失败页仍可按状态使用 `listening`、`thinking` 和 `sad`。

### 移动惯性反馈

三轴加速度相邻采样的突变量会映射成眼睛、头部和整张脸的短暂反向惯性，
随后由弹簧平滑回到当前倾斜目标。该反馈不维护摇动次数，也不会切换或覆盖
当前表情。

### 屏幕坐标与融合倾斜跟随

StopWatch 官方示例会交换 BMI270 原始 X/Y，得到与屏幕横纵方向一致的坐标。
当前固件沿用该映射：屏幕横纵运动分别驱动对应方向的倾斜与短暂惯性。

倾斜跟随不再只依赖低通加速度：陀螺仪提供转动瞬间的前馈，使眼睛先开始
移动；加速度计提供重力方向，使设备保持倾斜时视线仍停在相应位置。倾斜
幅度增大时，待机随机观察会逐渐淡出，避免自动视线与用户动作争抢。

当前倾斜约 `0.38 g` 达到最大映射。为防止表情长期偏离圆屏中心，基础横纵
行程限制为 `44 / 34` 个设计单位，陀螺前馈限制为 `8 / 6`，二者叠加后还要
经过 `47 / 36` 的椭圆安全区；对角倾斜不会再把两个轴的最大位移直接相加。
中心死区提高到 `0.11`，加速度低通和陀螺前馈也进一步减敏，接近边界时采用
软曲线并限制弹簧过冲。IMU 头部偏航/俯仰幅度进一步降为 `8° / 6°`，歪头限制
为 `1.5°`，仍保留眼睛先动、头部慢跟的
层次。该版本已通过
`pio run` 并烧录到 StopWatch，稳定窗口保持约 `60 fps`。方向、靠边距离
和不同握持方式下的主观手感仍属于真机调节项。

### 日常伴侣状态与 AMOLED 节能

设备新增一组保存在 ESP32 NVS 中的日常设置：正常亮度、无操作变暗时间、
AMOLED 熄屏时间以及安静时段。默认在 `45 s` 后将亮度降到 `24/255`，同时
把渲染调用限制为约 `20 fps`；`60 s` 后先清黑并把亮度设为零，再调用显示面板睡眠，但继续运行按键、
触摸和 IMU 采样，使三类输入都能恢复显示。动作唤醒在熄屏后有 `1.5 s` 保护期，
并要求连续两个超过阈值的 IMU 样本，避免面板刚睡眠就被轻微抖动误唤醒。这里没有宣称进入 ESP32
深度睡眠，实际电池收益仍需单独测量。

电量显示仍保持沉浸式状态表情：右眼剩余的白色开度直接代表当前电量，左眼保持
表情并承载简短文字；电量下降时右眼眼皮压低、头部下沉，低电量进一步切换到悲伤
或困倦情绪；充电时右眼固定按实测电量开合，左眼以轻微呼吸表达能量流入。
屏幕不显示时间、边框、电量环、图标或面板。中文状态短句收进左眼，
用 `24 px` 中文粗体黑字直接显示。文字以约 `420 ms` 柔和淡入，
停留期间做低幅明暗呼吸和亚像素级上下漂浮；约 `3.4 s` 后文字淡出，
角色先向一侧蓄力，再闭眼、连续甩头、短眨一次并带阻尼回弹，随后回到原基础表情。
长按 A 现在打开由双眼承载的五项根菜单。根菜单单击 A 在亮度、音量、夜静、网络和版本间
浏览，双击 A 确认，B 返回。亮度或音量页中单击 A 立即循环档位，右眼开度同步
表达档位。电量从菜单移到向下滑动手势，始终显示百分比和充电状态；约 `3.4 s`
后继续使用原有眨眼、甩头退出时间线，B 可提前返回。串口 `status` 也复用该显示。
“夜静”页显示定时静音开关，出厂默认关闭；单击 A 在“开/关”之间切换并写入 NVS。该开关只控制
`22:00–07:00` 内的音效静音，不取消 RTC 驱动的夜间困倦表情；时间范围仍可通过
串口 `quiet start end` 修改。
版本页为只读状态，左眼显示“版本”，右眼显示集中定义的固件版本号 `0.6.2`；B 返回，
A 不改变任何设置。启动日志和串口 `status` 使用同一版本常量，避免多个位置的版本漂移。
真机已确认根菜单依次到达 `5/5`，双击进入页面 `5`，串口状态同步报告

### 下滑电量后的偏移复位

下滑手势一旦达到电量触发阈值，主循环会立即从普通触摸分支切到状态分支，因此原先
普通分支收不到随后发生的 finger-up，`swipeActive_` 会保持为真并把双眼锁在下方。
`0.6.2` 在进入电量状态时主动调用 `releaseSwipe()` 并清理手势轴/提交标记，在状态退出
和状态内 finger-up 时再次防御性释放，确保电量表情与恢复后的基础表情都回到中心。
精确时间和电量仍可通过串口 `status` 查询。串口另提供 `time`、`brightness`、`volume`、
`dim`、`screenoff`、`quiet` 和 `screen on|off` 命令，用于首次校时、自动化
控制和参数验证。安静时段进入变暗状态时会让角色进入困倦姿态，任何有效唤醒
都会回到原基础表情。

2026-08-26 该版本通过 `pio run`，粗体字库、程序化音效和 TE 同步版本使用约 `9.4%` RAM 和 `23.1%` Flash，
并成功烧录到 StopWatch。真机串口完成以下验证：

- RX8130 写入并回读 `2026-08-26 20:12:45`；
- 电源接口报告约 `48%`、`3684-3686 mV` 且 USB 充电状态有效；
- 临时设置 `10 s` 变暗和 `15 s` 熄屏，两次状态转换均按时发生；
- `screen on` 能恢复 AMOLED；当前默认参数更新为 `45 s / 60 s`，并通过 NVS
  设置版本迁移把旧版默认的 `60 s / 300 s` 自动替换为新值；
- 正常亮屏窗口继续保持约 `59.7-59.8 fps`。GPIO 38 的 TE 上升沿同步在普通
  表情和快速甩头动画中均达到 `100%` 命中、`0` 超时；平均等待垂直空白约
  `5.2-6.7 ms`，包含等待的平均渲染耗时约 `13.6-14.1 ms`。

CO5300 初始化已打开 Tear Effect 输出，并把扫描线设在 `466`。渲染器使用 GPIO
38 上升沿中断捕获每次垂直空白，在开始脏矩形传输前等待下一沿；连续两次等待

沉浸式电量表情版本移除早期尝试的动态外圈和仪表式信息层。前一版真机在充电

把数值从屏幕移除，将能量映射下沉到眼皮和姿态。后续版本又把底部消息移入眼睛，
文字随眼睛一起参与局部脏矩形重绘，不需要额外的屏幕区域。

以上验证覆盖编译、烧录、RTC/电池读取和串口驱动的状态转换。状态页的文字

验收。

### 原创程序化 UI 音效

StopWatch 内置的 ES8311 编解码器和 AW8737A 功放通过 `M5.Speaker` 接入。音效
不使用人声，也不嵌入外部素材包；固件以正弦基音、轻泛音、短瞬态、滑音和
起音/衰减包络合成柔和的 pop、boop、blip，并分别映射到表情反应、前后切换、
状态打开/关闭、四档亮度、警告和屏幕唤醒。

所有变体在启动阶段一次性生成并缓存到 PSRAM，交互路径只提交 PCM 播放，避免
实时三角函数计算阻塞动画。连续三次串口 `sound` 测试保持约 `59.6 fps`、硬件
垂直同步 `100%`。默认主音量为 `56/255`，静音与四档音量保存到 NVS，现有 RTC
安静时段内自动跳过音效。

### 表情化 Wi-Fi 配网模式

第一阶段联网只实现配网和连接状态，不接入麦克风、语音识别或大模型。普通模式
普通界面长按 A 打开眼睛菜单，短按 A/B 均不切换表情；根菜单双击 A 只进入网络
状态页，默认以“网络/已连、未连或失败”报告状态。需要配网或换网时按住 A 才显示
“配网、换网或重试/按住”，继续按满约两秒才确认配网，B 取消或返回。子页面启用后还有
`350 ms` 输入隔离，避免根菜单的双击事件串入下一层。Wi-Fi 不再拥有普通界面的
独立按键快捷入口，避免误触打开热点或让用户记忆额外的按键层级。

用户明确确认重新配网时，设备会临时开放唯一的 `KK-XXXX` WPA2 热点，`XXXX` 是
由芯片唯一 ID 派生的末四位十六进制字符，只用于区分附近设备。本机实测为 `8428`。
固定配网密码为 `kkfriend`。通配 DNS 把手机的联网检测导向 `192.168.4.1`，网页
要求手动输入 2.4 GHz SSID，以避免 Wi-Fi 扫描让表情动画短暂停顿。网页只把路由器 SSID 和
密码交给设备；用户提交的路由器密码不写入源码、不输出到串口。新凭据先作为候选连接，只有实际联网成功后
才写入 `kk-avatar` NVS；若连接超时且存在旧凭据，设备自动恢复旧网络。配网热点
最多保持五分钟。

为避免把 `KK-XXXX` 的设备编号误当成热点密码，配网门户活动期间左眼显示 `kkfr`、
右眼显示 `iend`，合起来就是全小写的临时热点密码 `kkfriend`。这里只显示固件内固定
的临时热点密码，不读取或显示用户提交并保存在 NVS 中的路由器密码。

手表画面始终保持纯黑背景和程序化眼睛：静止时用 `curious` 搭配“网络/未连”，
已连接时用 `listening` 搭配“网络/已连”；只有按下 A 后才显示配网或换网提示，
热点开放后左眼显示 `kkfr`、右眼显示 `iend`，
`thinking` 搭配“网络/连接”，`sad` 搭配“网络/失败”。连接
成功后右眼开度映射 RSSI 信号强度；触摸仍只让当前表情的眼睛和头部跟随，不出现
网页式表单或矩形面板。网络服务由主循环非阻塞处理，配网期间暂停 AMOLED 自动
熄屏，退出后恢复原有电源策略。

该版本已通过完整 `pio run`；加入眼睛菜单、Wi-Fi、DNS 和 WebServer 后约使用
`17.6%` RAM 与 `30.4%` Flash。真机已完成 `KK-XXXX` 热点创建、手机门户凭据提交及
2.4 GHz 路由器连接，首次验证获得局域网地址、RSSI `-51 dBm`。联网后的
持续动画约为 `59.8 fps`、硬件垂直同步 `100%`，未观察到帧等待超时；启动热点时
ESP32 无线电初始化会产生一次约 `426 ms` 的模式切换停顿，稳定运行后不再重复。
安全交互版本烧录后仍能从 NVS 自动连接原 2.4 GHz 网络并维持约 `59.8 fps`；
长按 A 菜单的主观按键节奏仍应随实际使用继续微调。

### 网络自动校时

Wi-Fi 进入已连接状态后，主循环通过 Arduino ESP32 的 SNTP 接口请求阿里云、腾讯云
和公共池时间源，固定采用 `Asia/Shanghai` 的 `UTC+8` 本地时间。轮询使用零等待读取，
不会阻塞动画帧；十五秒未取得有效时间则暂停，一分钟后重试。成功后把时间写入
RX8130，并每六小时重新同步，使安静时段和夜间困倦逻辑不再依赖手动串口校时。
真机连接原有网络后同步到 `2026-08-27 16:54:18`，十一秒后通过独立 RTC 读取命令得到
`16:54:29`，确认时间已写入 RX8130；同步后的稳定动画约 `59.8 fps`，TE 同步 `100%`。

### 历史记录：已移除的局域网眼睛消息

以下内容记录 `0.7.0` 的实验实现与性能数据。用户验收后认为局域网消息用途有限，
`0.7.1` 已删除消息网页、POST API、单槽队列和 `local_message_server.*`，设备在 STA
联网后也不再启动 80 端口服务。Wi-Fi 配网与 NTP 自动校时继续保留；通用眼睛文字
渲染仍供菜单、状态页和 A+B 生日彩蛋使用。

`0.7.0` 新增独立的 `local_message_server.*`。设备只有在 STA 已连接时才启动
`GET /message` 和 `POST /api/message`；开始临时配网门户前先停止消息服务，STA
重新连接后再启动，避免两个 `WebServer` 同时占用 80 端口。页面只包含左右眼文字和
停留时间，不向设备画面引入网页式面板。

`POST /api/message` 只接受 `application/x-www-form-urlencoded`。`left`、`right`
均为必填，移除首尾空白后必须是有效 UTF-8、不得包含 C0/C1 控制字符，每侧最多
四个 Unicode 码点；完整编码请求体上限为 `128 B`。可选 `hold_ms` 默认 `3400`，
数值限制到 `1500–10000`。缺失、重复、未知、无效字段返回 `400`，请求体超过上限
返回 `413`，合法请求返回 `202`。响应和串口日志不回显消息正文或请求体，页面也不把

Wi-Fi 设置由单组凭据迁移为最多 `5` 个 `WifiProfile`。启动、断线和候选网络失败后使用
异步扫描，从当前可见的已保存 SSID 中选择 RSSI 最强者；扫描每信道上限采用 `300 ms`，
避免 Arduino ESP32 内部 `max_ms_per_chan * 20` 超时早于扫描完成。管理门户只显示 SSID，
可添加/更新或逐项删除，永不回显密码。候选项仍然只有连接成功后才进入 NVS。读取设置时
不把 `wifi_count` 当唯一事实来源，而是压实所有非空槽位，并无条件保留旧 `wifi_ssid`/
`wifi_pass` 迁移兜底；真机升级后确认原有 1 个配置恢复并自动连接。

公网阅读使用明确的 `KKREAD/1` 纯文本清单，而不在 ESP32 上抓取任意 HTML 或执行第三方
书源脚本。清单上限 `24 KiB`、`12` 个块；文字块沿用 `1800` 字/`96` 行输入边界和现有
打字机分页，图片块为绝对 HTTPS JPEG/PNG，单张上限 `768 KiB`，下载到 PSRAM 后按原始
宽高等比居中。文字末页淡出到黑场后再进入下一内容块；图片使用 `180 ms` 从左到右清黑，
A、短按 B 或点击继续，长按 B `1500 ms` 退出后通过独立睁眼状态恢复后台表情。

TLS 没有使用 `setInsecure()`。构建嵌入由 curl Mozilla CA extract 压缩出的 `121` 个根证书
集合，`WiFiClientSecure` 对清单和图片都执行证书校验；同协议重定向最多 `3` 次。局域网
`/read` 页面新增持久化书源地址的保存/清除，但它仍无身份验证，不应端口转发到公网。
清单正文和图片不写入 NVS。

最终 `pio run` 使用 RAM `64,768 / 327,680 B`（`19.8%`）和 Flash 约
`2.24 / 6.55 MB`（`34.2%`）。固件多次成功烧录并通过写入哈希校验。真机验证公开 HTTPS
证书成功、两块清单解析成功、23 字符文字页进入打字机、`8090 B` PNG 下载并识别，随后
长按退出路径恢复表情。正常表情稳定窗口约 `59.5–59.7 fps`；HTTPS 拉取是显式的加载
阶段，会短暂暂停动画。多 AP 漫游、更多 JPEG/PNG 尺寸与图片主观构图仍需用户目视验收。
