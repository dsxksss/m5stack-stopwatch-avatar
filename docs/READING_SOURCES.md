# KKREAD/1 公网阅读清单

`KKREAD/1` 是给资源受限的 KK 固件使用的纯文本交换格式。它描述一篇文章中
文字块与图片页的顺序，不包含脚本，也不要求固件抓取或理解任意网页。

## 最小示例

```text
KKREAD/1
TITLE: 小谷的周末
::TEXT
这是第一段正文。
可以正常换行，KK 会继续按圆屏安全区自动分页。
::END
::IMAGE https://example.com/books/weekend/01.jpg
::TEXT
图片后的文字会成为下一个内容块。
::END
```

规则如下：

- 第一行必须完全等于 `KKREAD/1`；
- 可选标题写作 `TITLE: 标题`；
- `::TEXT` 开始文字块，单独一行 `::END` 结束该块；
- `::IMAGE ` 后跟一个绝对 HTTPS JPEG 或 PNG 地址；
- 空行和以 `#` 开头的注释可以出现在内容块之外；
- 一个清单最多 12 个内容块；
- 每个文字块最多 1800 个 Unicode 字符、96 个显式行和 8192 字节；
- 清单最多 24 KiB，单张图片最多 768 KiB；
- 图片地址和清单地址都必须使用 HTTPS，不能包含用户凭据或 URL 片段。

文字中若确实需要一整行 `::END`，请拆成两个文字块，或在该行中加入普通字符。
当前版本只接受绝对图片地址，不解析相对路径。

## 内置书包

0.12.0 起，固件也可以从 SPIFFS 读取同样的 `KKREAD/1` 章节清单。轻量目录使用
`KKBOOK/1`，每行以 `::CHAPTER 相对路径|章节标题` 登记一个章节；设备端只接受
`manifests/*.kkread` 相对路径，拒绝路径穿越。当前内置《零灯》包含 42 个阅读单元，
章节、内容块和页码断点保存在 NVS。

仓库中的 `scripts/convert_markdown_book_to_kkread.ps1` 会保留原稿副本、生成完整
JSON 校验目录和设备端轻量目录，并确保每个清单符合本页限制。写入设备时只把
`catalog.kkbook` 与章节清单放入 SPIFFS，不把 Markdown 原稿重复写入设备。

## 托管与使用

把清单和图片放在任意可公开读取、证书有效的 HTTPS 静态托管服务即可，例如对象
存储、静态站点或仓库的 Raw 文件地址。服务器可以重定向，但重定向必须保持 HTTPS，
最多三次。固件使用随版本打包的 Mozilla 根证书集合进行服务器身份校验，不会跳过
TLS 验证。

1. 让 KK 连接 Wi-Fi。
2. 在同一局域网打开 `http://<设备地址>/read`。
3. 在“公网书源”中粘贴清单的 HTTPS 地址并保存。
4. 回到普通表情，长按 B 打开模式菜单，按 A 更新并阅读。
5. A 返回上一页或上一内容块，短按 B 或单击屏幕补完/继续；长按 B 满 1.5 秒退出。

文字第一页继续按 A 会进入上一内容块，并从该文字块最后一页开始；内置书籍还会跨到
上一章节。图片块遵循相同方向，A 上一块、B 下一块。章节选择页中 A 选择下一章、B
选择上一章、双击 A 阅读，长按 B 返回来源页。

把输入框清空后点击“保存 / 清除”即可删除已保存的公网书源地址。清单正文和图片
只在当次阅读中保留，不会写入 NVS。

## 安全边界

`/read` 是局域网配置入口，没有登录认证，因此只适合可信网络，禁止把设备 80 端口
转发到公网。公网下载只接受 HTTPS、限制响应体大小、拒绝非法 UTF-8 和非 JPEG/PNG
图片。它不执行 HTML、JavaScript、Legado 规则或远程固件。
